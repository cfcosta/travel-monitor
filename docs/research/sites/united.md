# United Airlines (united.com, UA): search URLs, price stream and calendar

- Date: 2026-10-06
- Method: `chrome-cdp` against the user's Chrome (one tab, XHR/fetch hook
  installed before navigation, 5 page loads), then a headless Chromium
  151 from the dev shell (`$TM_CHROMIUM`, `--headless=new`, fresh
  profile, 1 page load). The user's Chrome was **not** logged in to
  MileagePlus ("Acessar" in the header). No login, no award search, no
  flight selected.
- Test route: GRU→EWR. (`NYC` is rejected, see below.)
- Fixtures: [fixtures/united/](fixtures/united/README.md).

## Search URLs

A results page opens directly from a URL, with no form:

```
https://www.united.com/pt/br/fsr/choose-flights?f=GRU&t=EWR&d=2026-11-10&tt=1&sc=7&px=1&taxng=1&newHP=True&clm=7&st=bestmatches&tqp=R
https://www.united.com/en/us/fsr/choose-flights?f=GRU&t=EWR&d=2026-11-10&r=2026-11-17&sc=7,7&px=1&taxng=1&newHP=True&clm=7&st=bestmatches&tqp=R
```

Both were generated by hand and loaded in the user's Chrome; both
produced full results.

| Parameter | Meaning (observed) |
| --------- | ------------------ |
| path `/pt/br/`, `/en/us/` | Language and **point of sale**. `/pt/br/` priced in BRL, `/en/us/` in USD. |
| `f`, `t` | Origin and destination. Airport codes only: `t=NYC` returned an SSE `error` event, `minorCode 10042`, "destination airport code 'NYC' is invalid". |
| `d` | Outbound date `YYYY-MM-DD`. |
| `r` | Return date. With `r`, the request becomes a round trip (`SearchTypeSelection: 2`). |
| `tt=1` | One way (`SearchTypeSelection: 1`). Omitted for the round trip test. |
| `px=1` | Passengers (1 adult; `PaxInfoList: [{"PaxType":1}]`). |
| `tqp=R` | Revenue (cash). Award search would be a different value; not tested. |
| `sc`, `clm`, `st`, `taxng`, `newHP` | Copied from the site's own URLs. `st=bestmatches` is the sort. `sc=6,6` did not change `CabinPreferenceMain` (still `"economy"`). |

**Cabin does not need a parameter for cash fares.** One response holds
every cabin for each itinerary: United Economy (Basic, Standard,
Flexible), Premium Plus and Polaris business, each with its price.

## Where prices come from

### `POST /api/flight/FetchSSENestedFlights` (the result list)

Made by the results page with `fetch`, right after load. The request is
JSON ([fixture](fixtures/united/fetch-sse-nested-flights.request.json)):

```json
{"SearchTypeSelection":1,"SortType":"bestmatches",
 "Trips":[{"Origin":"GRU","Destination":"EWR","DepartDate":"2026-11-10",
           "SearchFiltersIn":{"FareFamily":"ECONOMY", ...}}],
 "CabinPreferenceMain":"economy","PaxInfoList":[{"PaxType":1}],
 "AwardTravel":false,"CalendarLengthOfStay":0, ...}
```

The response is a `text/event-stream` of `data: {json}` lines, 444 KB
for the one-way search, 540 KB for the round trip. Event `type`s, in
order: `meta`, `columns`, `farefamilies`, `specialPricingInfo`,
`airports`, `equipments`, `cabinCodes`, `flightOption` (one per
itinerary, 29 here), `progress` (`nonstop` then `stops`, "Completed"),
`flags`, `filters`, `teasers`, `streamingTimings`. Errors arrive as a
`type: "error"` event with HTTP 200.

Each `flightOption.flight` holds:

- `departDateTime`, `destinationDateTime` (`"2026-11-10 21:45"`, local),
  `origin`, `destination`, `marketingCarrier`, `flightNumber`,
  `operatingCarrier`, `travelMinutesTotal`, `equipmentDisclosures`;
- `connections[]`: the following segments, same shape;
- `products[]`: one per cabin column, each with `productType`
  (`ECO-BASIC`, `ECO-PREMIUM-BASIC`, `MIN-BUSINESS-OR-FIRST-BASIC`, …),
  `cabinType` (`Coach`, `PREMIUMPLUS`, `Business`), `bookingCode`,
  `fares[].fareBasisCode`, and `nestedProducts[]` for the dearer fare
  families of the same cabin (`ECONOMY`, `ECONOMY-UNRESTRICTED`, …);
- `prices[]` per product: `pricingType: "Fare"` is the **total per
  passenger including taxes** (`amount: 3549`, `currency: "BRL"`);
  `"Taxes"` (278) and `"saleFareTotalPrice"`/`"referencePrice"`
  (3270.75, the fare before taxes) are also present.

Sample (one way, `/pt/br/`, 2026-11-10): UA148 nonstop BRL 3,549 basic
economy, 4,048 standard, 8,086 Premium Plus, 17,754 Polaris. The list
also has UA connections via IAH, ORD and IAD, and Copa (CM) and Avianca
(AV) itineraries.

Round trip (`/en/us/`, 10–17 Nov): the outbound list prices the **whole
round trip**: UA148 USD 986 basic economy, 2,466 Premium Plus, 5,060
Polaris. The return list would come after choosing an outbound, which
we did not do.

The hook had to read the body as a stream (`response.clone().body`
reader). A plain `clone().text()` never recorded the call. The daemon's
`Page::capture` reads bodies through `Network.getResponseBody`, which
should work once the stream ends; that needs checking for
`text/event-stream`.

The home page called `GET /api/auth/anonymous-token` (an anonymous
session token, not saved); the results page did not repeat it. We did
not replay any API call outside the page.

### `POST /api/flight/FetchFlexibleCalendars` (the calendar)

Sent when "Mostrar calendário" / "Show calendar" is clicked on the
results page (an XHR, not a page load). The request is the search with
`"CalendarOnly": true, "FareCalendar": true`
([fixture](fixtures/united/fetch-flexible-calendars.request.json)).
The response is plain JSON:

```json
{"Data":{"CalendarPriceCells":[
  {"Cheapest":true,"Date":"2026-11-10","Fare":3549.0,"CurrencyCode":"BRL"},
  {"Date":"2026-11-13","Fare":3739.0,"CurrencyCode":"BRL"}, ...],
 "Status":1, ...}}
```

- **30 days per call**, starting at the searched date. The dialog's
  "Avançar 30 dias" button sends the same call with `DepartDate`
  moved forward (2026-12-10 → 30 days to 2027-01-08). So six months of
  one-way prices is **one page load plus about 6 clicks**.
- One way: the lowest fare per departure day, matching the result list
  (3,549 on 10 Nov in both).
- Round trip: the same call with `SearchTypeSelection: 2` and
  `CalendarLengthOfStay: 7` (the searched trip length) gives 30
  departure days of **round-trip prices at a fixed length of stay**
  (USD 986 on 10 Nov). That is exactly the 7-day series of 0042. The
  round-trip dialog also has a "+/- 3 day matrix" tab (not opened).
- The dialog says prices "were available within the last 24 hours":
  these are cached, not live. The round-trip call took 18.7 s.
- Only economy was seen (`CabinPreferenceMain: "economy"`). Whether a
  business calendar exists is open.

## Points of sale

The path selects it: `/pt/br/` (BRL), `/en/us/` (USD). Other
country/language paths presumably follow the same pattern; not tested.
Cookies `Locale` and `Session` are also set, but the path was enough.

## Bot protection

Akamai Bot Manager: cookies `_abck`, `bm_sz`, `bm_so`, `bm_lso`,
`bm_sv`, `akacd_*`, and sensor POSTs to an obfuscated path
(`/FFvp/Vfpe/...`, status 201). `window.fetch` is wrapped by an
obfuscated Akamai function.

- **User's Chrome:** no challenge in 5 loads (home, three result pages,
  one with an invalid code) and three calendar calls.
- **Headless Chromium** (`HeadlessChrome/151` user agent, which is what
  the daemon sends today): the first navigation, straight to the
  results URL, failed with `net::ERR_HTTP2_PROTOCOL_ERROR` and Chrome's
  "This site can't be reached" page. That is Akamai rejecting the
  connection at the edge. We stopped there, as agreed, without
  retrying or changing the user agent.

## Recommendation for the daemon

**Feasibility: possible.** The data side is very good: a generated URL,
one streamed response with every cabin and fare family, and a 30-day
calendar endpoint. The blocker is Akamai rejecting the headless
browser outright.

If the browser gets through:

1. Navigate to the generated `/{lang}/{country}/fsr/choose-flights?…`
   URL with `capture("FetchSSENestedFlights")` and
   `capture("FetchFlexibleCalendars")`.
2. Click the calendar button (`button` with text "Mostrar calendário"
   / "Show calendar", class `…sevenDayCalendarLink…`), then the
   forward button (`button.atm-c-calendar__btn`, "Avançar 30 dias")
   five times. Parse `CalendarPriceCells`.
3. Per route × point of sale × leg: 1 page load + 6 calendar calls for
   six months of one-way prices; the same again with `r=` for the
   7-day round trip. A specific date's full price list (all cabins) is
   one page load.

Risks: Akamai blocks the headless browser now; it may also start
challenging a busy profile. Calendar prices are up to 24 h old, so a
deal must be confirmed with a full search (0031). Only economy is in
the calendar. The SSE body must be readable through CDP.
