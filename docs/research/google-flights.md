# Google Flights: URL parameters, point of sale and internal RPCs

- Date: 2026-10-05
- Method: manual probing with `chrome-cdp` against the user's Chrome.
  Test search: SAO→LIS, economy, round trip 2026-11-10 to 2026-11-17.

## Search URLs

A search can be opened directly, with no form filling:

```
https://www.google.com/travel/flights?q=Flights%20from%20SAO%20to%20LIS%20on%202026-11-10%20through%202026-11-17&hl=en&gl=BR&curr=BRL
```

- `gl` sets the point of sale. The page footer confirms it
  ("Location: Brazil", "Location: United States" and so on).
- `curr` sets the display currency.
- Opening a flight leads to `/travel/flights/booking?tfs=…`. That URL
  encodes the exact itinerary and can be saved and replayed.

## Point of sale (`gl`) changes the OTA prices, not the airline price

The nonstop TAP flight (1:30 AM, GRU–LIS), with the display currency at
BRL:

| `gl` | TAP direct | Cheapest seller                     |
| ---- | ---------- | ----------------------------------- |
| BR   | R$4,122    | Kiwi.com R$3,932                    |
| PT   | R$4,122    | R$3,706                             |
| US   | R$4,122    | Flightnetwork R$3,728 ($746, in USD) |
| IN   | R$4,122    | BudgetAir R$3,739 (₹72,067, in INR) |
| CL   | (not opened) | cheapest-tab "from" R$3,848       |
| AR   | (not opened) | cheapest-tab "from" R$3,980       |

- The **Best** tab showed R$4,122 for TAP under every `gl`. That is the
  airline's own price, and it is the same everywhere.
- The **Cheapest** tab and the booking options show online travel
  agencies (OTAs). Under a foreign `gl`, they quote in their local
  currency. That is where the 5–8% spread comes from.
- The "Cheapest from" figure also changed between two loads with the
  same `gl` (R$3,980, then R$3,931). Single readings are noisy.

**Effective cost.** Paying a foreign seller with a Brazilian card adds
IOF (3.5%) plus the card's exchange spread. The US seller's R$3,728
becomes about R$3,858 before the spread. Against Kiwi's R$3,932 under
BR, that is only about 2% cheaper, and less than nothing with a typical
card spread. The cheapest foreign sellers (Flightnetwork, BudgetAir,
Mytrip) are also low-cost OTAs. On this route, foreign points of sale
are roughly a wash. They may still matter for business class or other
routes.

We did not test whether the OTA's own site, opened from a Brazilian IP,
honours the foreign price. That is where a VPN (Mullvad) would matter.

## Internal RPCs

The page talks to
`/_/FlightsFrontendUi/data/travel.frontend.flights.FlightsFrontendService/<Method>`
with a form body `f.req=[null,"<inner JSON>"]&at=<xsrf>`.

| Method               | What it returns                                                           |
| -------------------- | ------------------------------------------------------------------------- |
| `GetShoppingResults` | The result list.                                                          |
| `GetCalendarGrid`    | The date grid: a departure range × a return range.                        |
| `GetCalendarGraph`   | The price graph: a departure range with a fixed trip length (`[7,7]`).    |

`GetCalendarGraph` is the one we need. Its inner request is the search
(origin `/m/022pfm`, which is São Paulo's Freebase ID, destination
`LIS`, dates), then a departure range, then the trip length:

```json
[[…search…], ["2026-11-03", "2027-01-01"], null, [7, 7]]
```

Its response holds `[departure, return, [[null, price]]]` entries with
integer prices in the display currency. The first call covers about 60
days. Each "Scroll forward" in the price graph fetches 21 more days. Six
months of 7-day trips is about 7 calls per route and cabin.

Requests carry these headers:

- `X-Same-Domain: 1`
- `x-goog-ext-259736195-jspb: ["en-US","BR","BRL",1,null,[180],null,null,7,[]]`
  (locale, point of sale, currency)
- `X-Goog-BatchExecute-Bgr`: a BotGuard attestation token generated by
  the page's scripts.

**Direct calls do not work.** Every replay without a fresh BotGuard
token returns error `[13]`. That held with cookies and the `at` token,
from inside the page, and from outside it with no cookies. Forging or
replaying that token would mean getting around Google's bot protection,
so we will not do it.

**What does work.** The page itself makes these calls. A browser that
loads the search URL and opens the price graph produces
`GetCalendarGraph` responses. Reading them via CDP (`Network.getResponseBody`,
or an XHR hook as in this probe) gives exact prices without parsing the
DOM. The date grid's cells also have parseable aria-labels, such as
`"R$3,972, cheapest price, Nov 7 to Nov 18"`, which work as a fallback.

## Cabins and generated search URLs

- Date: 2026-10-06

The `q=` text understands "business class" and "first class". It does
not understand any phrasing of "premium economy": the parser drops the
destination and falls back to Explore.

The `tfs` parameter is a base64url protobuf that decodes and re-encodes
exactly. For a round trip:

```
1: 28                      (constant)
2: 2                       (constant)
3: { 2: "2026-11-10",      outbound leg: date,
     13: { 1: 2, 2: "/m/022pfm" },   from (1 = airport code, 2 = city ID)
     14: { 1: 1, 2: "LIS" } }        to
3: { … }                   return leg
8: 1                       one per adult passenger
9: 2                       cabin: 1 economy, 2 premium economy, 3 business, 4 first
14: 1
16: { 1: 2^64-1 }          no maximum price
19: 1                      trip type: round trip
```

URLs built from scratch with cabins 1–4 loaded correctly: the page
showed Economy, Premium economy, Business and First for SAO→LIS. Search
URLs can be generated in code for any route, dates, cabin and passenger
count. No UI navigation is needed. The same cabin number appears as
field 5 of the search inside the RPC requests.

City codes (like SAO) appear as Freebase IDs (`/m/022pfm`), not as
IATA codes. A city's ID can be learned once with a `q=` search and then
stored with the origin or destination. Single airports use their IATA
code with type 1.

## Explore

`https://www.google.com/travel/explore?q=Flights%20from%20SAO&hl=en&gl=BR&curr=BRL`
loads "1-week trip in the next 6 months" from São Paulo. Adding
"business class" to `q` sets the cabin (field 5 = 3 in the request).

The page makes one `GetExploreDestinations` call (about 1.4 MB). Each
of its destination entries holds:

- the destination's Freebase ID and airport code;
- the cheapest price, as an integer in the display currency;
- a token that includes the itinerary and dates, for example
  `GRU-LIS:2026-11-12_2026-11-19`;
- stops, total duration in minutes, and the carrier.

One call returned 72 destinations. The request includes the map
viewport in pixels (`[3040, 1959]`), which may limit how many
destinations come back. A larger browser window may return more.

Explore trips are "about a week" (6 to 9 days in this sample), not
exactly 7 days, and each destination has only one date pair. Explore
prices are therefore hints for the scheduler, not observations
comparable with the 7-day series.

Sample (economy, gl=BR): RIO R$718, SSA R$916, LIM R$1,491, BUE (AEP)
R$1,572, CUN R$2,053, MIA R$2,482, … LIS R$3,825.

## Round trip vs. two one-ways

- Date: 2026-10-06

Same dates, cabin and point of sale (economy, gl=BR), read from the full
result list. One-way searches are `tfs` with a single leg and field
19 = 2.

| Route (dates)              | Round trip | Out + return one-ways  | Sum     | RT discount |
| -------------------------- | ---------- | ---------------------- | ------- | ----------- |
| SAO–SSA (Nov 10–17)        | R$916      | R$462 + R$455          | R$917   | 0%          |
| SAO–BUE/AEP (Nov 10–17)    | R$2,429    | R$1,084 + R$1,628      | R$2,712 | 10%         |
| SAO–LIS (Nov 10–17)        | R$3,920    | R$1,827 + R$2,352      | R$4,179 | 6%          |
| SAO–MIA (Mar 4–11 2027)    | R$3,126    | R$1,845 + R$1,831      | R$3,676 | 15%         |

Nonstop only:

| Route | Round trip | Sum of one-ways | RT discount |
| ----- | ---------- | --------------- | ----------- |
| SSA   | R$916      | R$917           | 0%          |
| BUE   | R$2,554    | R$2,959         | 14%         |
| LIS   | R$3,951    | R$5,030         | 21%         |
| MIA   | R$4,534    | R$5,379         | 16%         |

The domestic route is additive: a round trip costs exactly its two
one-way fares. International round trips are 6–21% cheaper than the two
one-ways. Long-haul nonstop fares, which airlines price as round trips,
show the biggest gap. Google sometimes builds round trips from one-ways
itself ("Separate tickets booked together", seen on MIA via Arajet).

One-way searches have the same price graph: `GetCalendarGraph` with
field 2 of the search set to 2 and no trip length. It returns one price
per departure day: about 60 days on the first call, then 21 days per
"Scroll forward". The one-way date grid returns one week per call.

Cost per route × cabin × point of sale for six months:

- fixed-length round trip (price graph): about 7 calls;
- both legs one-way (two price graphs): about 14 calls, and gives every
  trip length;
- round trip at several lengths (date grid, departure week × return
  week): a few dozen calls.
